# W1-01：同步 vs 异步 最小对比

## 想搞清楚什么

**「发起」和「等待」是两件事。**

同步代码里它们被绑在一起（一调用就阻塞）。异步代码里可以先**把活儿全派出去**，再**统一等结果**。

再进一步的问题是：**是不是只要用了 `gather` 就会变快？**

不是。这个实验用第 ③ 类证明给你看。

## 怎么跑

**PyCharm**：目录树里右键 `sync_vs_async.py` → `Run 'sync_vs_async'`

**命令行**：

```bash
cd experiments/w1-01-sync-vs-async
python sync_vs_async.py
```

只用到标准库，不需要激活 venv。全程约 7 秒。

## 三类对比结果

| 类别 | 任务类型 | 并发方式 | 预期 | 实测 |
| --- | --- | --- | --- | --- |
| ① 同步串行 | I/O 密集 | 无（一个个等） | ≈ 3.0 秒 | 3.00 秒 |
| ② 异步并发 | I/O 密集 | `asyncio.gather` | ≈ 1.0 秒 | 1.01 秒 |
| ③ 异步并发 | **CPU 密集** | `asyncio.gather` | ≈ 3.0 秒 | 3.00 秒 |

**② 和 ③ 的写法完全一样** —— 都是三个协程塞进同一个 `gather`。
唯一区别：任务内部是在「等」还是在「算」。

## 结论

### 为什么 ② 比 ① 快？

> 答：`time.sleep(1)` 阻塞整个线程，冻结事件循环，无法并发；`asyncio.sleep(1)` 遇到 await 让出控制权，其他协程在这段时间里接着跑。

（注：严格说这是**并发**不是**并行** —— 见文末「一句话带走」。）

## 一句话带走

| 概念 | 含义 | asyncio 能给吗 |
| --- | --- | --- |
| **并发** concurrency | 单线程，把「等待时间」重叠起来 | ✅ 能 |
| **并行** parallelism | 多核各自真同时跑 | ❌ 不能（要用 `multiprocessing` / `ProcessPoolExecutor`） |

**asyncio 的全部收益都来自「有等待可以让出来」。** 没有等待，它一点忙都帮不上。

反过来说：LLM API 调用 99% 的时间在等网络 —— 这正是 asyncio 的主场，也是后面 P1 网关的底层依据。
